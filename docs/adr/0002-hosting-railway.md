# Хостинг — Railway, а не свой сервер на Hetzner

2026-11-04. Исследование стека ([.scratch/crm-mvp/issues/02-stack-and-hosting.md](../../.scratch/crm-mvp/issues/02-stack-and-hosting.md)) рекомендовало свой сервер Hetzner Cloud с Docker Compose и Caddy: дёшево (≈ €20–25/мес) и полностью под нашим контролем. Владелец выбрал Railway — управляемую платформу: службы (PostgreSQL, API, web, фоновые задачи) поднимаются из Dockerfile, TLS, домены, окружения staging и production и выкладка из GitHub — средствами платформы. Обслуживать сервер (обновления ОС, firewall, прокси, диски) не нужно.

Изоляция проектов от этого не меняется (ADR 0001): одна база PostgreSQL, row-level security, API работает ролью без обхода RLS, миграции — служебной ролью отдельным шагом.

## Considered Options

- **Hetzner Cloud + Docker Compose** (рекомендация исследования). Дешевле при постоянной нагрузке и без ограничений платформы, но сервер, резервные копии, TLS и мониторинг — на нас. Отвергнут владельцем.
- **Управляемый PostgreSQL (DigitalOcean, Supabase) + свой сервер приложений.** Запасной вариант исследования; две площадки вместо одной.

## Consequences

- Docker Compose остаётся только для локальной разработки; `docker-compose.yml` не является описанием production.
- Резервные копии с восстановлением на момент времени и объектное хранилище нужно подтвердить на Railway или вынести во внешнее S3-хранилище в ЕС — проверяется в тикете развёртывания.
- Стоимость зависит от потребления ресурсов, а не от фиксированного тарифа; её нужно измерить на staging.

# CRM сама не меняет сделки: автоматика — внешняя, через API и события

2026-11-04. В спецификации MVP были пять встроенных правил: оплата двигает этап и выигрывает сделку, пропущенный звонок ставит задачу «Перезвонить», автоархив сделок первого этапа через 30 дней, задача через 90 дней после выигрыша, назначение ответственного по кругу; строки товаров сами пересчитывали сумму сделки. Владелец решил иначе: система ничего не делает со сделкой по своей инициативе. Каждое действие человека или запроса API меняет ровно то, что в нём сказано: внесли сумму — меняется только сумма, пришёл платёж — записывается только платёж. Перемещение по этапам, выигрыш, назначение, задачи и архив по условиям делает внешняя автоматизация владельца через API.

Чтобы это работало, CRM даёт автоматизации две вещи:

- **Ключи API проекта.** Администратор проекта создаёт ключ и назначает ему роль; ключ может ровно то, что разрешает роль, работает только в своём проекте, каждое действие по ключу пишется в журнал с названием ключа. Правила, которые действуют для менеджера (обязательные поля с этапа, одна открытая сделка в воронке), действуют и для API.
- **События (исходящие вебхуки).** На адреса из настроек проекта CRM отправляет подписанные события с повторами: сделка создана, этап изменён, выиграна или проиграна, новая регистрация, платёж успешен или возвращён, звонок состоялся или пропущен, задача выполнена.

Запросы, которые сами по себе означают действие, CRM выполняет полностью: приём регистрации находит или создаёт контакт и добавляет регистрацию в открытую сделку или создаёт новую на первом этапе без ответственного (ответственного можно передать в запросе); запрос телефонии «кому направить звонок» получает ответ.

## Considered Options

- **Фиксированный набор встроенных правил с настройками** (исходное решение тикета 10 карты). Отвергнут владельцем: неожиданные изменения сделки системой, логика размазана между CRM и внешней автоматикой.
- **Конструктор автоматизаций внутри CRM, как в Pipedrive.** Был во второй очереди; не нужен, пока автоматика живёт снаружи.

## Consequences

- API для сделок, контактов, задач и архива — полноценная часть MVP, а не вспомогательная; его покрытие определяет, что может автоматизация.
- Сделки сами не уходят в архив: старые «Новий лід» архивирует автоматизация или менеджер массовой операцией.
- Если внешняя автоматизация не работает, сделки стоят на месте — это видно по событиям без реакции; мониторинг доставки событий входит в эксплуатацию.

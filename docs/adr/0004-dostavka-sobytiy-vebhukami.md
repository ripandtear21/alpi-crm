# Доставка событий вебхуками: хотя бы один раз, без порядка, тонкие события

2026-11-26. CRM отдаёт внешней автоматизации события через вебхуки проекта (ADR 0003: автоматика внешняя, CRM даёт ей ключи API и события). Здесь — как события доставляются. Доставка «хотя бы один раз»: одно событие может прийти больше одного раза, порядок не обещается. Автоматизация отбрасывает повтор по заголовку `webhook-id` и на порядок не опирается. Событие тонкое: id, неизменяемые факты изменения и автор (только тип и id), без имён, телефонов и email ([packages/shared/src/events/index.ts](../../packages/shared/src/events/index.ts)). Актуальное состояние сделки автоматизация читает через API своим ключом API. Так делают Stripe и Standard Webhooks (исследование `docs/research/webhook-delivery.md` на ветке `research/webhook-delivery`, разделы 1.3, 1.4, 2, 4.1). Реализация — тикет [crm-api/06](../../.scratch/crm-api/issues/06-webhook-delivery.md) (отправка событий на вебхуки), PR #32.

Правила доставки:

- **Один `webhook-id` на событие.** Он одинаков при всех автоматических повторах и при ручной повторной отправке.
- **Подпись по Standard Webhooks v1** (HMAC-SHA256 секретом подписи вебхука). После смены секрета 24 часа событие несёт две подписи — новым и старым секретом, чтобы автоматизация успела заменить секрет у себя.
- **Повторы.** Успех — только ответ 2xx. Иначе до 20 попыток с растущей паузой, пауза не больше 6 часов, всего около 2,5–3 суток. Потом доставка считается неудачной. Её можно отправить заново вручную в течение 30 дней: столько хранится журнал доставок.
- **Автоматическое отключение вебхука.** Ответ `410 Gone` отключает вебхук сразу. Ещё вебхук отключается, если 5 суток подряд не было ни одной успешной доставки, а попытки были. Серия неудач начинается заново, если с последней неудачи прошло больше 24 часов: повторы идут не реже раза в 6 часов, значит, сутки без попыток — это сутки, когда повторять было нечего. Пользователи с правом «интеграции» видят предупреждение в шапке, пока вебхук не включат снова или не удалят.
- **Только публичные адреса `https://`.** Адреса в частных сетях, loopback, link-local (в том числе адрес метаданных облака 169.254.169.254) и CGNAT отклоняются при сохранении вебхука и ещё раз перед каждой отправкой. Это защита от запросов CRM во внутреннюю сеть (SSRF).
- **Пока вебхук отключён, события на него не доставляются**, и после включения они сами не приходят.

## Considered Options

- **Строгий порядок событий для вебхука.** Отвергнут: одно событие, на котором автоматизация падает, останавливает все следующие события вебхука на время повторов (до ~3 суток) или до ручного вмешательства. К тому же Make по умолчанию обрабатывает входящие вебхуки параллельно, и порядок теряется уже у приёмника.
- **Ровно один раз.** Через сеть недостижимо: ответ автоматизации может потеряться после того, как она событие уже обработала.
- **Полные события с данными сделки.** Отвергнуты: персональные данные уходят из CRM в каждое событие. А при доставке не по порядку автоматизация получила бы устаревшее состояние сделки как свежее.
- **Новый `webhook-id` при ручной повторной отправке.** Отвергнут: автоматизация, которая событие уже обработала, обработала бы его второй раз — записала бы платёж или передвинула этап ещё раз.
- **Отсчёт 5 суток от последнего успеха.** Отвергнут: вебхук, на который долго ничего не отправлялось, отключался на первой же неудаче. Найдено проверкой кода доставки (PR #32).
- **Серия неудач, которую перерыв не обрывает.** Отвергнута: серия, начатая месяц назад, отключала уже починенный вебхук на одном ответе 503. Тоже найдено проверкой PR #32.

## Consequences

- Автоматизация обязана хранить `webhook-id` обработанных событий и не полагаться на порядок. В n8n и Make готового отбрасывания повторов нет — его строят сами.
- Если автоматизация событие обработала, но ответила ошибкой, ручная повторная отправка придёт с тем же `webhook-id` и будет отброшена как повтор.
- На каждое событие автоматизация делает хотя бы один запрос к API, чтобы прочитать актуальные данные; ключ API должен разрешать это чтение.
- Автоматизация, запущенная во внутренней сети Railway рядом с CRM, события не получит: ей нужен публичный адрес `https://`.
- События, случившиеся, пока вебхук был отключён, без отдельного действия потеряны для автоматизации. Догрузка с выбранной даты запланирована в тикете [crm-api/09](../../.scratch/crm-api/issues/09-webhook-catch-up.md): не раньше создания вебхука и не старше 30 дней, только типы, на которые вебхук подписан сейчас, только ещё не доставленные успешно; запускает пользователь с правом «интеграции», запуск пишется в журнал проекта.

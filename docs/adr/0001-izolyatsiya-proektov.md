# Проекты полностью изолированы друг от друга

2026-11-03. В Pipedrive AI-школа ALPI и франчайзинг-консалтинг «Франч» живут в одном аккаунте: контакты, поля, товары и справочники общие, данные двух бизнесов перемешаны. В своей CRM каждый бизнес — отдельный **проект**, и данные проектов не пересекаются никак: свои контакты, организации, сделки, воронки, пользовательские поля, товары, причины проигрыша, типы задач и интеграции (мерчант WayForPay, проект Ringostat, ключи приёма регистраций). Один и тот же человек в двух проектах — два независимых контакта. Общие для системы только учётные записи пользователей (доступ и роль выдаются на каждый проект отдельно, в интерфейсе — переключатель проекта) и справочник курсов НБУ. Поиск и отчёты всегда в пределах одного проекта.

Технически — одна база PostgreSQL, у каждой записи метка проекта, изоляцию обеспечивает сама база через row-level security (политика «видишь только строки текущего проекта»), чтобы ошибка в коде приложения не показала данные чужого проекта.

## Considered Options

- **Общий контакт на оба проекта, как в Pipedrive.** Отвергнут: владелец хочет, чтобы бизнесы не пересекались, а общий контакт тянет за собой общие права, общие дубли и путаницу «чей клиент».
- **Отдельная база (или отдельная установка CRM) на каждый проект.** Изоляция сильнее, но на каждое изменение схемы — две миграции, вдвое больше инфраструктуры, а пользователю с доступом к обоим проектам — два входа. Для двух проектов одной группы компаний не окупается.

## Consequences

- Каждая таблица бизнес-данных несёт метку проекта, и каждый запрос выполняется в контексте одного проекта; задачи без такого контекста (курсы НБУ, служебные фоновые задачи) должны явно работать вне политик.
- Сводный отчёт «по группе компаний» возможен позже только как отдельный отчёт владельца, читающий оба проекта осознанно.

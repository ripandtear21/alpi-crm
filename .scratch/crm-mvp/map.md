# Карта: MVP своей CRM вместо Pipedrive

Labels: wayfinder:map

## Destination

Спецификация MVP своей CRM (`.scratch/crm-mvp/spec.md`): сущности, экраны, правила, интеграции, стек и хостинг — настолько полная, что её можно нарезать на тикеты реализации без новых вопросов. Реализация — отдельная работа после карты.

## Notes

- Домен: CRM для двух проектов (изолированных бизнесов) одной группы компаний — AI-школа ALPI / Franch AI (B2C: вебинар → бронь → счёт → доплата) и франчайзинг-консалтинг «Франч» (B2B). Сейчас оба работают в Pipedrive `franch.pipedrive.com`.
- Источники: `docs/research/pipedrive.md` (как устроен Pipedrive), `docs/research/our-pipedrive.md` (как настроен наш аккаунт), `GLOSSARY.md` (термины).
- Скиллы для каждой сессии: `grilling` + `domain-modeling` на grilling-тикетах, `research` на research-тикетах, `prototype` на prototype-тикетах. Термины сразу вносить в `GLOSSARY.md`.
- Язык документов и общения — русский.
- Исходные условия (решено при постановке карты, 2026-11-03):
  - Зачем: глубже связать CRM со своими системами (школа, оплаты, реклама, мессенджеры) и снизить расходы (Pipedrive ≈ €1,9 тыс./мес).
  - Первым переезжает проект AI-школы ALPI, «Франч» — вторым, на той же системе. Модель с первого дня держит несколько полностью изолированных проектов (ADR 0001).
  - Только для своих компаний, не SaaS: без изолированных аккаунтов.
  - Сущности «лид» нет — только сделки. Каждая регистрация на вебинар — сделка на первом этапе. CRM рассчитана на сотни тысяч сделок; нужно массовое закрытие старых сделок «Новий лід».
  - Валюты: EUR, UAH, USD. Отчёты — в гривне по курсу НБУ на дату закрытия сделки, с фильтром «в исходной валюте».
  - Данные из Pipedrive пока не переносим, но модель готовим к будущему импорту. Период параллельной работы: новые сделки — в новой CRM, старые дорабатываются в Pipedrive.
  - Интеграции MVP: приём регистраций (API/вебхук с UTM, fbclid, gclid), WayForPay (оплата двигает сделку), Ringostat (звонки в истории сделки). Вторая очередь: Telegram/Wazzup/ManyChat, KWIGA/Zenedu, Zapier.
  - Пользовательские поля — через конструктор полей (админ сам добавляет поле), с группами, обязательностью, свои в каждом проекте.
  - Строит владелец вместе с Claude Code. Уклон стека — TypeScript целиком + PostgreSQL; окончательный выбор — тикетом.
  - Срок-ориентир: 2–3 месяца до параллельного запуска для AI-школы.
  - Интерфейс: украинский по умолчанию, с переводами (для «Франча» нужен русский); адаптивный веб, пригодный для телефона.

## Decisions so far

<!-- одна строка на закрытый тикет: [название](issues/NN-slug.md): суть ответа -->

- [API внешних сервисов MVP: WayForPay, Ringostat, НБУ](issues/03-external-apis.md): частичных оплат в WayForPay нет — бронь/счёт/доплата отдельными платежами, связь хранит CRM; списание только в UAH; вебхуки Ringostat сверять ночью через API; курс НБУ брать по явной дате (Киев).
- [Стек, хостинг и требования к объёму](issues/02-stack-and-hosting.md): рекомендация — Hono + React SPA (Vite, TanStack), PostgreSQL 18 + Kysely, поля в JSONB, Better Auth, pg-boss, i18next; Hetzner + Docker Compose ≈ €20–25/мес.
- [Модель данных ядра](issues/01-core-data-model.md): проекты ALPI и «Франч» изолированы полностью (ADR 0001, row-level security); контакт внутри проекта, поиск по телефону/email, слияние дублей; сделка — один этап, одна валюта, архив; у сделки список регистраций с полными рекламными данными; платежи и простой каталог товаров.
- [Роли, права и видимость](issues/07-roles-and-visibility.md): конструктор ролей в каждом проекте — таблица «часть системы × действие» + охват (свои / команды / все) + права на группы полей; 4 шаблона ролей, одна роль на проект, обязательная двухфакторная аутентификация, передача сделок при уходе.
- [Задачи и «следующая задача»](issues/08-activities.md): типы задач свои в проекте; задача на день или на время; индикатор следующей задачи (вычисляемый); предложение следующей после выполнения; звонки Ringostat — события ленты, пропущенный создаёт «Перезвонить»; календарь задач внутри CRM, внешние календари и уведомления вне CRM — вторая очередь.

## Not yet specified

- **Отчёты.** Какие отчёты и дашборды реально нужны руководителям обоих проектов (конверсия по этапам, оплаты, эффективность менеджеров, атрибуция рекламы). Зависит от модели данных и того, что смотрят в Pipedrive Insights сейчас.
- **Второй проект — «Франч».** Чем его воронки, поля и роли отличаются настолько, что требуют особых решений (организации, B2B-сделки с несколькими контактами).
- **Интеграции второй очереди.** Мессенджеры (Telegram/Wazzup/ManyChat), учебные платформы (KWIGA/Zenedu), Zapier — что именно синхронизировать.
- **Параллельная работа с Pipedrive.** Нужна ли хоть какая-то связь между системами на переходный период (поиск контакта в обеих, защита от дублей).
- **Эксплуатация.** Резервные копии, мониторинг, развёртывание, кто и как поддерживает систему.
- **Уведомления и поиск.** Какие уведомления получают менеджеры (новая сделка, просроченная задача, оплата) и как ищут по сотням тысяч сделок.

## Out of scope

- Продажа CRM как SaaS и изолированные аккаунты для многих компаний — решено при постановке карты: только для своих компаний.
- Отдельная сущность «лид» — решено: только сделки.
- Нативное мобильное приложение — решено: адаптивный веб.
- Сам перенос данных из Pipedrive — в этой карте только подготовка модели к импорту.

## Question

Как работает конструктор пользовательских полей: какие типы полей нужны (по итогам аудита полей), группы полей, привязка к направлению и воронке, обязательность (всегда / при переходе на этап), стабильный код поля вместо хэш-ключей, редактирование и удаление поля с данными, поля у контактов и организаций, какие поля системные (сумма, валюта, этап, владелец, UTM) и не настраиваются.

## Answer

**Решено без владельца по его поручению (2026-11-04, «разрешаю все решения») — подтвердить.** Решение о самом конструкторе не зависит от аудита полей (тикет 05); аудит нужен для перечня полей к переносу — это вход тикета «Готовность к импорту из Pipedrive». Основа — `docs/research/our-pipedrive.md`, раздел 2.

- **Где живут поля**: у сделок, контактов, организаций; каждое поле принадлежит одному проекту (ADR 0001). У задач и товаров пользовательских полей нет (в Pipedrive их тоже нет).
- **Типы**: текст, большой текст, число, деньги (сумма + валюта), дата, время, интервал дат, один вариант, несколько вариантов, да/нет, телефон, email, ссылка, адрес (текстом), пользователь (сотрудник проекта). Поля-формулы — не в MVP (в Pipedrive 0 из 10).
- **Группы**: поле состоит в одной группе; группы упорядочены и сворачиваются в карточке. Права ролей задаются на группу: «видно и можно менять» / «только чтение» / «скрыто» (тикет «Роли, права и видимость»).
- **Видимость по воронкам**: поле сделки показывается во всех воронках проекта или в выбранных.
- **Обязательность**: «всегда» или «начиная с этапа X» выбранной воронки — сделку нельзя перевести на этап X и дальше (и выиграть), пока поле пусто. Отметка «важное» — подсветка в карточке без запрета.
- **Код поля**: стабильный латинский код (по умолчанию из названия), правится до появления первого значения, потом неизменен. Используется в API, импорте и фильтрах вместо хэш-ключей Pipedrive. Название можно менять когда угодно.
- **Варианты списков**: у каждого варианта стабильный идентификатор; переименование не трогает данные; вариант можно «архивировать» — он не предлагается для новых значений, старые остаются.
- **Смена типа** у поля с данными — только безопасные: текст → большой текст, один вариант → несколько вариантов, число → текст. Иначе — новое поле.
- **Удаление** поля с данными = архивирование (скрыто, данные целы); окончательно удаляет администратор через 30 дней. Поле без данных удаляется сразу.
- **Фильтры и скорость**: значения в JSONB с GIN-индексом (тикет «Стек, хостинг и требования к объёму»); отметка «часто фильтруют» у поля строит для него отдельный индекс.
- **Системные поля — не в конструкторе**: у сделки название, воронка, этап, статус, сумма, валюта, ответственный, причина проигрыша, архив, даты создания/закрытия/смены этапа, ожидаемая дата закрытия; у контакта имя, фамилия, телефоны и email (несколько, с пометкой «основной»), организация, язык общения; у организации название, адрес, сайт. Рекламные данные — не поля, а **Регистрация** (тикет «Модель данных ядра»).
- **Что из Pipedrive не станет пользовательскими полями**: группы «Метки» и «Разное» (UTM, fbclid/gclid, referrer, user_agent, rs_utm_*) и рекламные поля «Вебинара» → данные регистрации; данные о вебинаре и просмотре (Webinar ID, дата, название, «Начал/Закончил смотреть», минуты и процент просмотра) → данные регистрации на вебинар; «Сделка WFP», «Страница оплаты» → платёж; «Bitrix ID» → внешний идентификатор (тикет «Готовность к импорту из Pipedrive»). Остальные группы (Квалификация, Franch AI, Встреча, Курс, ВПК) — кандидаты в пользовательские поля своих проектов; окончательный список — по аудиту полей.

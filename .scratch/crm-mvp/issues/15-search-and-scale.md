## Question

Как менеджер находит нужное среди сотен тысяч сделок и контактов: глобальный быстрый поиск (по имени, телефону в любом формате, email, названию сделки, организации), фильтры и сохранённые фильтры (группы условий И/ИЛИ, по пользовательским полям, по индикатору следующей задачи, по данным регистраций), скорость списков и канбана при десятках тысяч сделок на этапе, массовые операции над результатом фильтра.

## Answer

**Решено без владельца по его поручению (2026-11-04, «разрешаю все решения») — подтвердить.**

- **Быстрый поиск** в шапке, в пределах текущего проекта и охвата роли: по имени контакта, телефону (любой формат приводится к единому), email, названию сделки, организации; результаты сгруппированы по типу. Полнотекстовый поиск PostgreSQL (триграммы для имён и названий); отдельный поисковый сервис не нужен.
- **Фильтры**: условия по системным и пользовательским полям, по индикатору следующей задачи, по данным регистраций (источник, кампания, вебинар), по архиву; группы условий И/ИЛИ; сохранённые фильтры — личные и общие для команды/проекта (общие — по праву).
- **Большие списки**: постраничная выдача через курсор, счётчик «≈» для больших результатов; канбан грузит по ~50 карточек на этап с подгрузкой при прокрутке, суммы и количество по этапам считаются запросом агрегатов, а не по загруженным карточкам; первый этап ALPI по умолчанию показывает «ещё N — открыть списком».
- **Массовые операции** над результатом фильтра (архивировать, передать, сменить этап, удалить) выполняются фоновой задачей с прогрессом и журналом; права — тикет «Роли, права и видимость».
- **Ориентир скорости**: список и канбан до 1 с при 500 тыс. сделок в проекте на сервере из тикета «Стек, хостинг и требования к объёму»; проверить нагрузочным тестом на сгенерированных данных до запуска.

## Question

Что входит в эпик конструктора полей (15 типов, группы с правами ролей, видимость по воронкам, обязательность «всегда» и «с этапа X» — одинаково для менеджера и API, коды полей, архив, названия uk/ru), как он режется на тикеты и волны, какие стартовые поля ALPI заводятся по разбору `docs/research/pipedrive-fields-audit.md` (≈ 45 полей), и как поля появляются в карточке, списке, фильтрах и будущем API. Результат — папка эпика со `spec.md` и тикетами. Источник — раздел 12 «Эпик 7» спецификации и тикет карты MVP «Пользовательские поля: конструктор».

## Answer

Решено с владельцем 2026-11-04. Конструктор — как в тикете карты MVP «Пользовательские поля: конструктор» (подтверждён владельцем в третьем раунде). Эпик `crm-fields` (`.scratch/crm-fields/`), 9 тикетов в 5 волнах:

1. Описания полей и групп: база, API `/api/v1`, коды, варианты, архив.
2. Значения (хранение JSONB, проверка по типу, API значений) · права ролей на группы («видно и можно менять» / «только чтение» / «скрыто»; скрытое не отдаётся и через API).
3. Обязательность «всегда» и «с этапа X» — одинаково на канбане, в карточке, при выигрыше и в API · экран конструктора · поля в карточках сделки, контакта, организации (группы, правка на месте, «важное») · поля в списке, фильтрах, сохранённых фильтрах и на карточке канбана (до 3 полей, выбирает администратор), ускорение «часто фильтруют» строится в фоне.
4. Стартовые поля ALPI: таблица ≈ 45 полей по `docs/research/pipedrive-fields-audit.md` (название, тип, группа, обязательность) — владелец просматривает до заведения.
5. Приёмка автотестом: завести поле, заполнить, отфильтровать, обязательность с этапа, скрытая группа под менеджером.

Изменения полей пишутся в историю сделки «было → стало». Запреты дизайна Actum относятся только к Actum: альтернативные направления остаются как есть до выбора владельцем.

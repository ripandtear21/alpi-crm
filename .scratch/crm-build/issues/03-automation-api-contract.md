## Question

Каким будет внешний API, через который автоматизация владельца двигает сделки (ADR 0003): ключи API проекта с ролью и журналом, адреса и версии (`/api/v1`), формат ошибок, постраничная выдача, защита от повторов (ключ идемпотентности), какие действия со сделками, контактами, задачами и архивом доступны в MVP; каталог событий (сделка создана, этап, выигрыш/проигрыш, регистрация, платёж, звонок, задача выполнена), их содержимое, подпись, повторы и журнал доставки; как это режется на тикеты эпика «API для автоматизации и события». Результат — папка эпика со `spec.md` и тикетами.

## Answer

Решено с владельцем 2026-11-04. Эпик `crm-api` (`.scratch/crm-api/`), 8 тикетов в 4 волнах:

- **Ключи API**: создаёт администратор проекта, название и роль; показывается один раз, в базе — отпечаток; отзыв и перевыпуск, срок по желанию; `Authorization: Bearer …`; действия по ключу — в журнале под его названием.
- **Общие правила**: `/api/v1/...`, JSON; ошибки в формате RFC 9457 (код, текст, поле); курсорная выдача; `Idempotency-Key` для повторов без дублей; 600 запросов в минуту на ключ; описание API из кода на `/api/v1/docs` (для браузера, n8n, Make).
- **Действия в MVP**: сделки — создать, поля и сумма, этап, ответственный, выиграть, проиграть с причиной, открыть заново, в архив, перенести в другую воронку; контакты и организации — создать, изменить, найти по телефону или email; заметки; задачи — когда будет эпик задач; справочники только чтение (воронки, этапы, причины, пользователи, команды). Удаления через API нет.
- **События**: сделка создана, этап, выиграна/проиграна/открыта заново, ответственный, архив, регистрация, платёж успешен/возвращён, звонок состоялся/пропущен, задача создана/выполнена, контакт создан, возможный дубль; подписка адреса на выбранные типы. Тело тонкое: id, тип, время, id сущности, что изменилось, кто сделал (сотрудник или ключ — чтобы автоматизация не зацикливалась на своих изменениях).
- **Доставка**: хотя бы один раз, без обещания порядка; повторы ≈ 3 суток; адрес, не отвечающий 5 суток, отключается с уведомлением администратору; журнал доставок 30 дней, ручной повтор; подпись — Standard Webhooks (HMAC, защита от повтора). Событие пишется в той же транзакции, что изменение (тикет «Надёжная доставка событий»).
- **Тикеты**: 1) ключи API · общие правила; 2) запросы сделок · контакты, организации, справочники · хранение событий в транзакции; 3) доставка (подпись, повторы, отключение, журнал, ручной повтор) · экран «События»; 4) приёмка: тестовый приёмник получает подписанные события и двигает сделку через API без зацикливания. События платежей, звонков, регистраций и задач добавят их эпики по образцу.

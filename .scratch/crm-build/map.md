# Карта: план реализации MVP после фундамента

Labels: wayfinder:map

## Destination

План реализации всего MVP после эпика `crm-foundation`: переписанный раздел 12 спецификации (`.scratch/crm-mvp/spec.md`) — состав и порядок эпиков — и у каждого эпика своя папка `.scratch/<эпик>/` с описанием (`spec.md`) и тикетами, готовыми к работе, как у `crm-foundation`. MVP готов, когда ALPI может параллельно запуститься на новой CRM.

## Notes

- Домен и решения: `.scratch/crm-mvp/spec.md` (особенно раздел 13.0 — ответы владельца 2026-11-04), `GLOSSARY.md`, ADR `docs/adr/0001` (изоляция проектов), `0002` (хостинг Railway), `0003` (CRM сама не меняет сделки — автоматика внешняя через API и события).
- Скиллы: `grilling` + `domain-modeling` на grilling-тикетах, `research` на research-тикетах. Термины — сразу в `GLOSSARY.md`.
- Язык документов и общения — русский.
- Исходные условия (решено владельцем при постановке карты, 2026-11-04):
  - Порядок эпиков: 1) сделки, воронки, контакты; 2) конструктор полей; 3) API для автоматизации и события; 4) приём регистраций; 5) платежи WayForPay и курсы НБУ; 6) задачи и лента; 7) Unitalk; 8) отчёты; 9) запуск — Railway, резервные копии, мониторинг, нагрузочный тест.
  - Отдельный эпик «API для автоматизации и события» сразу после сделок и полей; каждый следующий эпик добавляет свои запросы и события.
  - Один эпик за раз; внутри эпика — параллельные волны тикетов.
  - Экраны эпика сделок — по прототипу `docs/prototypes/crm-mvp-screens/index.html`; правки владельца после просмотра — в начале эпика или отдельным тикетом.
  - В каждом эпике — команда заполнения локальной базы правдоподобными данными (тысячи сделок), без данных из Pipedrive.
  - Эпик закрывается после ручной приёмки владельцем по короткому сценарию на локальной сборке; агент проходит тот же сценарий в браузере заранее.
  - Ориентир — 2–3 месяца до параллельного запуска ALPI (≈ эпик в неделю); план пересматривается после эпика сделок.
  - До готовности MVP всё работает локально; выкладка на Railway — в эпике запуска.
  - После `crm-foundation` слияние в main — только через pull request с зелёной проверкой GitHub.

## Not yet specified

- Нарезка эпиков 4–9 (приём регистраций, платежи, задачи и лента, Unitalk, отчёты, запуск) на тикеты — после решений по сделкам, полям и API: от них зависят модели и форматы запросов. Каждый, вероятно, станет отдельным тикетом карты.
- Ручная проверка WayForPay на тестовом мерчанте (поля колбэка для счёта в EUR, максимальный срок жизни счёта, частичные возвраты) — перед эпиком платежей (пункт 45 спецификации).
- Детали запуска на Railway: версия PostgreSQL, резервные копии с восстановлением на момент времени, объектное хранилище для записей звонков, цена (ADR 0002).
- Чек-лист готовности к параллельному запуску ALPI и порядок переключения источников регистраций с Pipedrive (раздел 11.4 спецификации).

## Out of scope

- Перенос данных из Pipedrive — модель к нему готова, сам перенос вне MVP.
- Переезд «Франча», интеграции второй очереди (Telegram, Wazzup, ManyChat, KWIGA, Zenedu), конструкторы автоматизаций и отчётов — после MVP (подтверждено владельцем 2026-11-04).
- Встроенная автоматика сделок (автоархив, назначение по кругу, задачи по условиям, движение по оплате) — по ADR 0003 её делает внешняя автоматизация владельца.
- Нативное мобильное приложение — адаптивный веб.

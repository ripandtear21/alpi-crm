## Что сделать

Начинается после слияния эпиков `crm-deals` и `crm-fields` целиком (`.scratch/crm-api/spec.md`, «Зависимость от эпиков»).

Ключ API — доступ внешней автоматизации к одному проекту с ролью этого проекта. Ключ не пользователь: у него нет пароля, 2FA, команды и своих сделок.

Миграция (следующий свободный номер миграции), таблица с `project_id` и RLS:

- `api_key` — проект, название (обязательно, до 100 символов, уникально среди действующих ключей проекта), роль проекта, отпечаток секрета (SHA-256, уникален), первые 8 символов секрета для показа, кто создал, `created_at`, `expires_at` (по желанию), `revoked_at`, кто отозвал, `last_used_at`. Строка ключа не удаляется: журнал ссылается на неё.
- Функция `SECURITY DEFINER` (по правилам `packages/db/migrations/0003_projects.ts`): по отпечатку возвращает id ключа, проект и роль, только если ключ не отозван и срок не истёк. Больше ничего она не умеет и ничего не читает.
- У `audit_log` и `change_log` — ссылка на ключ как автора (`actor_api_key_id`); автор записи — пользователь, ключ или никто, но не оба сразу (ограничение в базе).
- Роль, на которой есть действующий ключ, удалить нельзя — 409 (решено без владельца — подтвердить).

Секрет:

- Формат `alpi_` и 32 случайных байта (`node:crypto`) в base64url (решено без владельца — подтвердить). Показывается один раз — в ответе на создание и перевыпуск; в базе только отпечаток. Ни в журнал, ни в логи сервера секрет не попадает.
- Перевыпуск — новый секрет, старый перестаёт работать сразу (решено без владельца — подтвердить).

Проверка запроса — промежуточный слой перед контекстом проекта (`apps/api/src/middleware/`):

- Заголовок `Authorization: Bearer <секрет>` — запрос ключа; cookie сессии в таком запросе не читается (решено без владельца — подтвердить). Нет такого заголовка — прежний путь сессии без изменений.
- Ключ найден функцией по отпечатку → контекст проекта ключа (`withProject`), права — по роли ключа через тот же `loadMemberAccess` / `requirePermission` / `scopePredicate`, что у пользователя. Роль читается на каждом запросе: смена прав роли действует сразу.
- Охват для ключа: «все» — все записи; «свои» и «команда» — только сделки общей очереди, потому что у ключа нет своих сделок и команды (решено без владельца — подтвердить).
- `X-Project-Id` не нужен; если передан и не совпадает с проектом ключа — 403 `PROJECT_FORBIDDEN`.
- Неизвестный, отозванный и истёкший ключ — одинаковый 401 `API_KEY_INVALID`, чтобы ответ не выдавал, был ли ключ (решено без владельца — подтвердить).
- Ключ проходит только на маршруты с отметкой «доступно ключу» (функция-отметка на маршруте, список ведут тикеты 03 и 04); любой другой маршрут — 403 `API_KEY_NOT_ALLOWED` при любой роли, в том числе администратора. Так ключ не может управлять ключами, ролями, участниками, адресами событий и журналом.
- `last_used_at` обновляется не чаще раза в минуту, чтобы не писать в базу на каждый запрос.

Журнал (решено без владельца — подтвердить, что нужны оба):

- Каждое изменяющее действие по ключу пишется в историю записи (`change_log`) с автором-ключом и в журнал действий проекта (`audit_log`) с id ключа; экран журнала показывает название ключа и пометку «ключ API».
- Создание, перевыпуск и отзыв ключа — в журнал опасных действий (`apps/api/src/audit/record.ts`), с кодами действий в `packages/shared/src/audit.ts`.

Запросы `/api/v1/api-keys` (только по сессии): список (название, роль, первые 8 символов, кто и когда создал, срок, последний запрос, отозван ли), создать, перевыпустить, отозвать. Право: «интеграции» (`integrations`: смотреть — список; создавать, изменять, удалять — остальное) и «пользователи и роли: изменять» (`users_roles: edit`), потому что выдать роль ключу — то же, что выдать её участнику (решено без владельца — подтвердить). По шаблонам ролей это администратор. Название ключа после создания не меняется (решено без владельца — подтвердить).

Экран «Налаштування → Ключі API» (uk, ru; 375 px): список ключей; диалог создания — название, роль, срок по желанию, предупреждение, если охват роли не «все»; окно с секретом и кнопкой «скопіювати» и текстом «більше не буде показано»; перевыпуск и отзыв с подтверждением.

Проверка: нужна линза безопасности (`security`).

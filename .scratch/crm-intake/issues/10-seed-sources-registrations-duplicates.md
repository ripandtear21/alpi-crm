## Что сделать

`pnpm seed` дополняется данными этого эпика, чтобы владелец и автотест приёмки (тикет 11) видели экраны «Джерела», «Дублі», регистрации в карточках и откат слияния на правдоподобном объёме. Только выдуманные данные (`apps/api/src/seed/names.ts`), без данных из Pipedrive.

Что создаётся в каждом проекте, детерминированно от зерна генератора (`apps/api/src/seed/random.ts`):

- Источники: 3–4 на проект («Вебінар», «Консультація», «Лендінг курсу», один отключённый), каждый со своей воронкой; ключи источников печатаются в файл учётных данных `pnpm seed` рядом с паролями, а не в вывод.
- Тысячи регистраций (доля как у сделок `pnpm seed`), привязанных к сделкам первого этапа и дальше: формы, вебинары, тарифы, адреса страниц, правдоподобные `utm_*`, `fbclid`/`gclid`/`fbp`/`fbc`, `user_agent`, `extra`; у части — просмотры вебинара. У части сделок — по несколько регистраций.
- Журнал входящих за последние 30 дней: принятые, повторы, ошибки (400 без телефона и email), просмотры «без регистрации».
- Готовые дубли каждого правила тикета 05: один телефон в разной записи, email в разном регистре, пара с пометкой «возможный дубль», одинаковые имя и фамилия с совпадением последних 9 цифр, контакт с архивной и открытой сделкой в одной воронке, пара контактов с открытыми сделками в одной воронке (для тикета 04), группа из трёх контактов, одна пара с отметкой «не дубль».
- Несколько слияний: свежие (откат доступен) и старше 30 дней (откат недоступен), одно с вложенным слиянием сделок.
- После заполнения — прогон надсмотрщика, чтобы «Дублі» и счётчик в шапке сразу были не пустыми.

Данные создаются через функции приложения (приём регистрации, слияние), а не прямой вставкой, где это не мешает скорости: так данные проходят те же проверки.

## Where in code

apps/api/src/seed/**, apps/api/src/cli/** (команда `pnpm seed`), при необходимости apps/api/src/intake/**, apps/api/src/merge/**, apps/api/src/duplicates/**.

- [ ] Тест изоляции: данные каждого проекта — только в своём проекте; регистрация не ссылается на сделку другого проекта.
- [ ] Тест: экран «Дублі» на данных `pnpm seed` показывает группы каждого правила; одно свежее слияние откатывается, старое — нет.
- [ ] Ночной проход надсмотрщика на данных `pnpm seed` полного объёма — время в отчёте (порог тикета 05).
- [ ] Ключи источников не попадают в вывод команды и в журнал сервера.
- [ ] `pnpm verify` зелёный.

## Что сделать

Списки сделок, контактов и организаций — таблица с выбором колонок (выбор запоминается у пользователя), сортировкой по колонке и курсорной подгрузкой. Счётчик результатов: точное число до порога, выше — оценка со знаком «≈».

Фильтры по системным полям (у сделок: воронка, этап, статус, ответственный, «без відповідального», сумма, валюта, даты создания, смены этапа, выигрыша и проигрыша, причина проигрыша, архив; у контактов и организаций — их системные поля) с группами условий И/ИЛИ. Условия фильтра — один формат и одна функция построения запроса на сервере, которую принимает и выдача канбана; кнопку фильтра в канбане подключает тот из тикетов 11 и 12, который сливается вторым. Пользовательские поля, регистрации и «следующая задача» в фильтрах добавят их эпики. Архивные сделки по умолчанию скрыты.

Сохранённые фильтры (`saved_filter`, следующий свободный номер миграции, `project_id`, RLS): личные, для команды, для проекта. Сохранять для команды и проекта — отдельное право «общие фильтры» (подтверждено владельцем, пункт 32): добавить `shared_filters` в каталог `packages/shared/src/permissions.ts` и в шаблоны — администратор и руководитель для проекта, тимлид для команды, менеджер нет. Фильтр команды видят её участники.

Массовые действия над выбранными строками или над всем результатом фильтра, через каркас тикета 04 с прогрессом и журналом: архивировать, вернуть из архива, передать (сменить ответственного или в общую очередь), сменить этап в пределах воронки, удалить в корзину. Право — «массовые операции» плюс право самого действия (передача — «передача сделок», удаление — «сделки: удалять») и охват на изменение для каждой записи. Возврат из архива проверяет правило «одна открытая сделка» и пишет конфликты в журнал операции. Главный сценарий: архивировать старые сделки «Новий лід» фильтром «этап = первый, создана раньше даты».

Выгрузка в CSV по праву «выгрузка в файл» (`export`): текущие колонки и фильтр, с учётом охвата, потоком; выгрузка пишется в журнал опасных действий.

Корзина: экран «Налаштування → Кошик» — удалённые сделки, контакты и организации, дата окончательного удаления, восстановить (право «корзина: изменять»), удалить окончательно (право «корзина: удалять»). Зарегистрировать сделки, контакты и организации в реестре окончательного удаления через 30 дней (тикет 04).

Тикет не отправляет событий; массовые действия выполняются только по команде пользователя (ADR 0003). Экраны на компонентах тикета 01, uk и ru, на 375 px таблица прокручивается по горизонтали.

## Результат

- Формат фильтра — `packages/shared/src/filters` (группы `{and:[…]}` / `{or:[…]}`, условия «поле — оператор — значение», белые списки полей и операторов по сущности, глубина ≤ 3, ≤ 50 условий; `parseFilter` проверяет одинаково в браузере и на сервере). Построение запроса — `apps/api/src/filters/compile.ts`: имя поля из запроса до SQL не доходит (колонка берётся из таблицы соответствий), значения — только параметры; тест «только параметризованный SQL» проверяет это на попытке инъекции.
- Тот же фильтр принимает выдача канбана: `dealsWhere` / `listDealsPage` в `apps/api/src/deals/board.ts` читают параметр `filter` и `sort`; колонки и агрегаты канбана берут фильтр из кнопки «Фільтр» на канбане. Курсор канбана по умолчанию прежнего вида, для других сортировок — курсор «значение + id» (`apps/api/src/filters/page.ts`).
- Списки: `/deals/list` (все статусы, архив скрыт без условия «Архів»), `/contacts` (заглушка заменена списком), `/organizations` (новый пункт левого меню «Організації»). Колонки выбираются в диалоге и запоминаются в браузере по пользователю и списку; сортировка — кнопками заголовков на сервере; «Показати ще» — курсор; счётчик точный до 10 000, выше — оценка планировщика со знаком «≈». Ссылки «Список» и «ще N — відкрити списком» с канбана переносят воронку, этап, фильтр и ответственного в адрес списка.
- Сохранённые фильтры: таблица `saved_filter` (миграция `0014_saved_filters`, `project_id`, RLS `project_isolation`, тест изоляции в `project-isolation.test.ts`), API `/v1/saved-filters`. Новое право `shared_filters` («Спільні фільтри») — в шаблонах руководителя и тимлида; миграция дописывает его существующим ролям руководителя и тимлида.
- Массовые действия сделок на каркасе тикета 04 (`apps/api/src/deals/bulk.ts`): архивировать, вернуть из архива (проверка «одной открытой сделки»), передать (нужно ещё право «передача угод»), сменить этап (только в пределах воронки сделки), удалить в корзину. Выбор — отмеченные строки или «всі N за фільтром»; диалог показывает прогресс и записи с ошибкой. Запись вне охвата не меняется и пишется в журнал операции.
- Выгрузка CSV: `GET /v1/{deals,contacts,organizations}/export.csv` с правом «експорт», текущими фильтром, сортировкой и колонками; UTF-8 с BOM, ячейки, похожие на формулу, экранированы; выгрузка пишется в журнал действий (`export.downloaded`). Данные идут порциями по 500, каждая — в своей транзакции проекта.
- Корзина: `GET /v1/trash?type=deal|contact|organization` (охват роли), экран «Налаштування → Кошик» со вкладками, восстановлением (конфликт «одной открытой сделки» — с подсказкой) и окончательным удалением с подтверждением; новый `DELETE /v1/deals/:id/permanent` (право «Кошик: видаляти», журнал `deal.purged`). Очистка старше 30 дней — задачей по расписанию тикета 04, для сделок, контактов и организаций (`apps/api/src/trash/purgers.ts`).
- Номер миграции: `0014_saved_filters`. Номер 0013 занят открытым PR тикета 08 (быстрый поиск); если тикет 08 сливается после этого, его миграция переименовывается в `0015`.
- не проверено: пункт 8 «Done when» (настоящий браузер на 1280 и 375 px) — проверка в браузере не входила в задачу исполнителя; вёрстка проверена только тестами экрана, которые ширину не отрисовывают. В доработке (раунд 1) редактор фильтра снят Playwright на собранном клиенте с подменённым API — 1280 и 375 px, светлая и тёмная темы; остальные экраны в браузере не смотрели.

Решено без владельца — подтвердить:

- Фильтр «для всего проекта» сохраняет только тот, у кого есть право «Спільні фільтри» и охват чтения сделок «усі» (или администратор); тимлид — только для своей команды, без команды — отказ `NO_TEAM`.
- Выбор колонок хранится в браузере (localStorage), а не на сервере: на другом устройстве — колонки по умолчанию.
- Даты в фильтре — полночь выбранного дня в часовом поясе браузера (ISO-время).
- У фильтра контактов нет телефона и email (они в отдельных таблицах); организация и ответственный в фильтре — выбор из списка, организация — ввод id.
- Массовые действия — только для сделок; у контактов и организаций в этом тикете их нет.
- Массовая смена этапа не проверяет обязательные поля этапа (их проверяет смена этапа из карточки и канбана).

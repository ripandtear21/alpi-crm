## Что сделать

Экран «Угоди» по умолчанию — канбан выбранной воронки (выбор воронки запоминается). Колонки — этапы; показываются только открытые неархивные сделки (решено без владельца, подтвердить), удалённые этапы не показываются.

- Карточка: название, основной контакт, сумма с валютой, ответственный (или «без відповідального»), место под индикатор следующей задачи (заполнит эпик задач).
- Подгрузка: каждая колонка грузит около 50 карточек и подгружает остальные при прокрутке курсором (`GET /api/v1/deals?pipeline=…&stage=…&cursor=…`). Колонка, где сделок больше порога (например 500), в конце показывает «ще N — відкрити списком» со ссылкой на список с фильтром этого этапа.
- Шапка колонки: количество и суммы по каждой валюте отдельно. Их считает отдельный запрос агрегатов `GET /api/v1/pipelines/:id/aggregates` с тем же охватом и фильтрами, а не загруженные карточки. Итог в UAH по курсу НБУ добавит эпик платежей.
- Перетаскивание между колонками меняет этап (запрос смены этапа тикета 05); при ошибке карточка возвращается на место с сообщением. Перетаскивание на зону «Виграно» выигрывает сделку, на «Програно» — открывает диалог выбора причины (группа → причина, без архивных).
- Обязательные поля: в смене этапа API (тикет 05) — точка расширения «проверить требования этапа», которая возвращает список незаполненных полей; сейчас всегда пусто, наполнит эпик полей. Если список не пуст — API отвечает 422 со списком, экран показывает его. Правило одно для экрана и API (ADR 0003).
- Общая очередь: фильтр «без відповідального» и кнопка «Взяти в роботу» на карточке без ответственного.
- Фильтры канбана: ответственный (я, участник команды в охвате, без ответственного). Конструктор фильтров списка (тикет 12) подключает к канбану тот из тикетов 11 и 12, который сливается вторым.
- Кнопка «+ Угода» — форма создания сделки: контакт (поиск существующего или новый, ответ «чужий клієнт» показывается текстом «клієнт уже в роботі у <менеджер>»), воронка и этап, название (предзаполнено «Ім'я Прізвище — »), сумма и валюта, ответственный (по умолчанию я). Конфликт «одна открытая сделка» показывает подсказку и ссылку на открытую сделку.
- Телефон (уже 768 px и меньше): одна колонка, этапы — вкладками с количеством; перетаскивания нет, этап меняется выбором в меню карточки; выигрыш и проигрыш — там же.
- Охват соблюдается сервером: экран показывает ровно то, что отдал API.

Тикет не отправляет событий; экран меняет сделку только действием пользователя (ADR 0003).

## Результат

- API, `apps/api/src/deals/board.ts`:
  - `GET /api/v1/deals` — страница сделок с курсором. Параметры: `pipeline=<uuid>`, `stage=<uuid>` (оба необязательны); `owner=me|none|<id пользователя>` (я, без ответственного, участник); `status=open|won|lost|any` (по умолчанию `open`); `archived=false|true|any` (по умолчанию `false`); `limit=1…200` (по умолчанию 50); `cursor=<nextCursor прошлой страницы>`. Ответ — `{ items: BoardDeal[], nextCursor: string | null }`; карточка — id, название, воронка, этап, сумма, валюта, ответственный и его имя, основной контакт и его имя (null, если контакт вне охвата контактов), время смены этапа. Порядок — `stage_changed_at desc, id desc`; курсор — непрозрачная строка base64url с временем смены этапа (до микросекунд, UTC) и id последней сделки: следующая страница строго после неё, равные даты не дают повторов и пропусков. Курсор действует только с теми же фильтрами; испорченный — 400 `INVALID_DEAL` с `path: cursor`. Сделки в корзине не отдаются никогда; охват — как у карточки (свои / команда / все плюс общая очередь).
  - `GET /api/v1/pipelines/:id/aggregates` — `{ stages: [{ stageId, count, sums: { EUR?, UAH?, USD? } }] }` по тем же фильтрам и охвату (`owner`, `status`, `archived`); считает база. Этап без сделок в ответ не попадает. Чужая воронка — 404.
  - `GET /api/v1/deals/owners` — действующие участники проекта в охвате чтения сделок (для фильтра «участник команды»).
  - Для тикета 12: `listDealsPage(ctx, filters, { cursor, limit, extra })` и `pipelineAggregates(ctx, filters, extra)` принимают дополнительное условие WHERE `extra: DealCondition` (`(eb) => Expression<SqlBool>` на таблицу `deal`) — сюда подключается построитель фильтров. Курсор разбирает `decodeCursor`.
- Требования этапа — `apps/api/src/deals/stage-requirements.ts` (`StageRequirements.missingFields(db, deal, stageId)`, по умолчанию `NO_STAGE_REQUIREMENTS` — пусто). Смена этапа (`POST /deals/:id/stage`) с непустым списком отвечает 422 `STAGE_REQUIREMENTS_MISSING` с `details.fields`; сделка остаётся на месте, в историю ничего не пишется. Подключается через `createApp({ stageRequirements })`.
- Экран `/deals` (`apps/web/src/routes/deals/`): канбан выбранной воронки (выбор запоминается в `localStorage` по проекту), фильтр ответственного (все, мои, без відповідального, участник), колонки с числом и суммами по валютам из агрегатов, подгрузка по 50 при прокрутке до 500 карточек, дальше — ссылка «ще N — відкрити списком» на `/deals/list?pipeline=…&stage=…` (экран списка — тикет 12). Перетаскивание между колонками, на «Виграно» и «Програно» (диалог группа → причина, только действующие). Карточка сразу переезжает, отказ API возвращает её с сообщением. Меню карточки (смена этапа, выигрыш, проигрыш) — на всех ширинах; на телефоне (≤ 768 px) — одна колонка, этапы вкладками с числом, перетаскивания нет. Карточка — `apps/web/src/components/deal-card/`. Форма «+ Угода» — `new-deal-dialog.tsx`.

Решено без владельца — подтвердить:

- Колонка канбана упорядочена по времени прихода на этап: недавно пришедшие сверху (перетащенная карточка встаёт наверх колонки).
- Требования этапа проверяются только при смене этапа в своей воронке; перенос в другую воронку и создание сделки их пока не спрашивают.
- Имя основного контакта на карточке показывается, только если контакт в охвате чтения контактов пользователя; иначе — «контакт поза вашим охопленням».

## Что сделать

Общие редакторы значений по 15 типам — `apps/web/src/components/custom-fields/` (их же использует форма заполнения тикета 04): текст и большой текст, число, деньги (сумма и валюта EUR/UAH/USD), дата, время, интервал дат, один вариант и несколько вариантов (без архивных вариантов для выбора; уже выбранный архивный показан с пометкой «архів»), да/нет, телефон (клик — `tel:`), email (`mailto:`), ссылка (открывается в новой вкладке, `rel="noopener noreferrer"`), адрес, пользователь (выбор из активных участников проекта; отключённый, уже выбранный, показан с пометкой). Проверка перед отправкой — общей функцией из `packages/shared/src/fields/`; ошибка сервера показывается у поля.

Карточки сделки, контакта и организации (эпик `crm-deals`):

- Блоки групп по порядку групп, внутри — поля по порядку; группа сворачивается, состояние запоминается у пользователя. Пустые поля показаны (чтобы их заполнить), пустая группа — нет.
- Правка на месте: нажатие на значение открывает редактор, сохранение — запросом изменения записи с одним кодом в `custom`; при ошибке старое значение возвращается с сообщением.
- Группа «только чтение» — значения без редактирования; скрытая группа не приходит с сервера и не показывается.
- Видимость по воронкам: в карточке сделки только поля, видимые в её воронке; после переноса в другую воронку невидимые поля пропадают, их значения сохраняются.
- «Важливе»: пустое важное поле подсвечено (решено без владельца, подтвердить), запрета нет.
- Поле, обязательное на текущем этапе или дальше по воронке, помечено подсказкой «обов'язкове з етапу X».
- Лента: изменения пользовательских полей показываются как остальные «було → стало», с текущим названием поля и названиями вариантов.

Экраны на компонентах основы дизайна, uk и ru, на 375 px поля идут одной колонкой.

Тикет не отправляет событий; значения меняются только действием пользователя (ADR 0003).

## Результат

- Общие редакторы значений по 15 типам — `apps/web/src/components/custom-fields/` (`field-editor.tsx`, `field-values.ts`, `custom-field-groups.tsx`, клиент `custom-fields-api.tsx`); ими же пользуется форма заполнения тикета 04. Ссылка `javascript:` не сохраняется и показывается текстом; http(s) открывается с `rel="noopener noreferrer"`.
- Карточки сделки, контакта и организации показывают группы полей после основных блоков: видимость по воронкам, группа «только чтение» без редактора, скрытая группа не выводится, пустое «важное» подсвечено, подсказка «обов’язкове з етапу …» только для воронки сделки. Правка на месте — `PUT` записи с одним кодом в `custom`; на 422 `CUSTOM_FIELD_INVALID` значение откатывается и у поля показывается причина.
- Лента: строка `custom.<код>` показывается текущим названием поля и названиями вариантов. Строки переводов — новое пространство имён `custom-fields` (`apps/web/src/locales/{uk,ru}/custom-fields.json`, путь тикета `apps/web/src/i18n/locales` не существует).
- Пункт 7 (375 px): not verified в тикете — снимки проверяющего PR #23 (`deal|contact|organization-375-{light,dark}.png`, в отчёт не приложены) показывают поля в одну колонку.

Решено без владельца — подтвердить:

- Свёрнутые группы запоминаются в `localStorage` браузера под id пользователя, не на сервере (`shortcut:` в `custom-field-groups.tsx`).
- Без права «пользователи и роли» (`GET /members` — 403) в поле «пользователь» можно выбрать только себя; чужое значение показывается как «Користувач».
- Подсказка обязательности показывается для любого правила «с этапа» воронки сделки, в том числе для этапа раньше текущего.

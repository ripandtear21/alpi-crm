Type: task

## Что сделать

Миграция (следующий свободный номер миграции), все таблицы с `project_id` и RLS:

- `field_group` — тип сущности (`deal` / `contact` / `organization`; группа принадлежит одному типу — решено без владельца, подтвердить), название uk и ru, порядок.
- `field_definition` — тип сущности, группа (того же типа), код, название uk и ru, тип (один из 15: `text`, `long_text`, `number`, `money`, `date`, `time`, `date_range`, `single_option`, `multi_option`, `boolean`, `phone`, `email`, `url`, `address`, `user`), порядок в группе, видимость по воронкам (все воронки проекта или список воронок; только у полей сделки), правила обязательности (нет / «всегда» / список «воронка → этап, с которого обязательно»; этап — этап этой воронки или «выигрыш»; только у полей сделки, кроме «всегда»), отметка «важное», отметка «часто фильтруют», `first_value_at` (время первого значения — ставит тикет 02), `archived_at`.
- `field_option` — поле, стабильный id, название uk и ru, порядок, `archived_at`. Только у типов «один вариант» и «несколько вариантов».

Правила, все — и в базе, и в API:

- Код: латиница в нижнем регистре, цифры и `_`, начинается с буквы, до 63 символов; уникален в проекте и типе сущности (среди живых и архивных полей); коды системных полей сущности (`title`, `stage`, `amount`, `currency`, `owner`, `status` и т. п. — список в `packages/shared`) запрещены (формат — решено без владельца, подтвердить). По умолчанию код строится из украинского названия транслитерацией; пользователь может его поправить. Код меняется, только пока `first_value_at` пуст и поле не отмечено «часто фильтруют» (второе — решено без владельца, подтвердить); потом неизменен. Название меняется когда угодно.
- Название группы, поля и варианта обязательно на украинском; русское необязательно, при отсутствии показывается украинское (решено без владельца, подтвердить).
- Варианты: переименование и смена порядка не трогают данные (значения хранят id варианта). Архивный вариант не предлагается для новых значений, старые значения остаются. Удаления варианта нет — только архив.
- Тип меняется свободно, пока у поля нет значений. Смена типа поля с данными (только безопасная: текст → большой текст, один вариант → несколько вариантов, число → текст) — тикет 02; здесь API отвечает 409 на любую смену типа поля с `first_value_at`.
- Видимость и обязательность ссылаются только на воронки и этапы своего проекта; правило «с этапа X» допустимо только для воронки, в которой поле видно. Удаление этапа, на который ссылается правило, переводит правило на следующий этап воронки (решено без владельца, подтвердить).
- Удаление поля с данными = архив: поле скрыто отовсюду, данные целы, можно вернуть. Окончательное удаление — действием администратора, доступно не раньше чем через 30 дней после архивирования; само по расписанию поле не удаляется (решено без владельца, подтвердить). Оно убирает ключ поля из `custom` всех записей фоновой задачей порциями (pg-boss), потом удаляет описание; код освобождается. Поле без данных удаляется сразу. Окончательное удаление пишется в журнал опасных действий (`apps/api/src/audit/record.ts`).
- Группу с полями (в том числе архивными) удалить нельзя; пустую — можно (решено без владельца, подтвердить).
- Создание поля не меняет ни одной записи.

Запросы `/api/v1/field-groups` и `/api/v1/fields` (`?entity=deal|contact|organization`): список, создать, изменить, порядок групп и полей, архивировать, вернуть из архива, удалить; `/api/v1/fields/:id/options` — добавить, изменить, порядок, архивировать. Менять — право «поля» (`fields`: создавать, изменять, удалять). Читать описания может каждый с правом смотреть эту сущность (решено без владельца, подтвердить); скрытые от роли группы из ответа убирает тикет 03. Общие типы описаний, список 15 типов и правила кода — в `packages/shared/src/fields/`, чтобы клиент и сервер проверяли одинаково.

Тикет не отправляет событий и ничего не делает сам (ADR 0003); события — в эпике API.

## Where in code

packages/db/migrations/**, packages/db/src/schema.ts, packages/shared/src/fields/** (типы, коды, транслитерация), apps/api/src/fields/**, apps/api/src/app.ts (маршруты), apps/api/src/jobs/** (задача окончательного удаления), apps/api/src/pipelines/** (перевод правил при удалении этапа).

## Done when

- [ ] Миграции применяются на чистую базу и откатываются.
- [ ] Тест изоляции: описания, группы и варианты проекта A не видны в контексте B без фильтра в коде.
- [ ] Тест прав: создание, изменение и удаление поля без права `fields` — 403; чтение описаний с правом смотреть сущность — 200.
- [ ] Тесты кода: код по умолчанию из украинского названия («Головний мотив» → `holovnyi_motyv`); дубликат кода в проекте и типе сущности, код системного поля и код не по формату — 422; смена кода при заполненном `first_value_at` или при отметке «часто фильтруют» — 409; смена названия при этом проходит.
- [ ] Тест вариантов: переименование варианта не меняет его id; архивный вариант не попадает в список предлагаемых, но остаётся в описании поля.
- [ ] Тест: правило «с этапа X» с этапом чужого проекта или воронки, где поле не видно, — 422; «с этапа X» у поля контакта — 422.
- [ ] Тест архива: поле с данными при удалении уходит в архив, а не удаляется; окончательное удаление раньше 30 дней — 409; после — задача убирает ключ из `custom` всех записей, описание удалено, код снова свободен, запись в журнале опасных действий есть. Поле без данных удаляется сразу.
- [ ] Тест: группу с полем удалить нельзя (409), пустую — можно.
- [ ] `pnpm verify` зелёный.

# Права ролей на группы полей

Type: task
Status: open
Blocked by: 01

## Что сделать

Три уровня доступа роли к группе полей: «видно и можно менять» (`edit`), «только чтение» (`read`), «скрыто» (`hidden`) — `FIELD_GROUP_ACCESS` в `packages/shared/src/permissions.ts`.

Каталог прав:

- `parsePermissions` сейчас требует пустой `fieldGroups`. Теперь он принимает `{ id группы: доступ }` с доступом из `FIELD_GROUP_ACCESS`; сервер дополнительно проверяет, что каждый id — группа этого проекта. Группа без записи — по правам части системы её сущности: `edit`, если роль может изменять сделки (контакты, организации), иначе `read`. Удалённая группа убирается из прав всех ролей.
- Роль «администратор» всегда имеет `edit` на все группы; записать ей `read` или `hidden` — 422 (роль администратора нельзя урезать).
- Защита от расширения прав (`apps/api/src/roles/guard.ts`): не-администратор не выдаёт роли доступ к группе выше своего (`edit` > `read` > `hidden`); проверяется только добавляемое, как для остальных прав.
- Одна функция «доступ роли к группе» и «какие коды поля роль видит / может менять» для всего сервера.

Где скрытое не отдаётся (здесь — для API тикетов 01 и 02 и для истории; список, фильтры, выгрузку и канбан подключает тикет 07):

- описания: `/api/v1/field-groups` и `/api/v1/fields` не возвращают скрытые группы и их поля;
- значения: из `custom` в ответах сделки, контакта и организации убираются коды скрытых полей;
- история: записи `change_log` по скрытым полям не отдаются ни в ленте, ни в ответах истории;
- запись: поле группы `read` — 403; поле группы `hidden` — 422 как неизвестный код, чтобы ответ не выдавал существование поля (решено без владельца, подтвердить). Значения скрытых полей при изменении записи не теряются.

Экран: в редакторе ролей («Налаштування → Ролі») раздел «Групи полів» — таблица групп по сущностям с выбором доступа; у администратора — только `edit`, без выбора. Тот же запрос использует диалог группы в конструкторе (тикет 05).

Тикет не отправляет событий (ADR 0003).

## Результат

- Каталог прав (`packages/shared/src/permissions.ts`): `parseRolePermissions` принимает `fieldGroups: { id группы: доступ }` — ключ должен быть id (uuid, приводится к нижнему регистру, ключи упорядочены), доступ — из `FIELD_GROUP_ACCESS`; иначе 400 `INVALID_ROLE`. `fieldGroupAccessRank` — порядок «скрыто» < «только чтение» < «изменять».
- Одна функция доступа — `fieldGroupAccess(permissions, group)` (`packages/shared/src/fields/index.ts`): запись роли о группе, а без записи — «изменять», если роль может изменять сущность группы (сделки, контакты, организации), иначе «только чтение». Администратор действует с `fullPermissions()` без записей — у него всё «изменять». Сервер берёт её через `apps/api/src/fields/access.ts` (группы проекта, видимость группы и поля, список видимых строк истории); тот же расчёт показывает редактор ролей.
- API ролей (`apps/api/src/roles/roles.ts`): id в `fieldGroups`, который не группа этого проекта, — 422 `FIELD_GROUP_NOT_FOUND` (`details.path`); группы блокируются `FOR KEY SHARE`, удаление группы ждёт записи роли. Роли администратора записать «только чтение» или «скрыто» — 422 `ADMIN_FIELD_GROUPS_LOCKED` (остальные изменения роли администратора по-прежнему 409 от базы).
- Защита от расширения прав (`apps/api/src/roles/guard.ts`): не-администратор не выдаёт доступ к группе выше своего — сравнение по каждой группе проекта, в том числе без записи (иначе роль без записи с правом изменять сделки получила бы «изменять» на группу, которая у выдающего «только чтение»); проверяется только поднятое. Действует для создания и изменения роли, назначения роли и изменения участия — поэтому `apps/api/src/members/service.ts` (вне списка файлов тикета) передаёт в проверку группы проекта.
- Удаление группы (`apps/api/src/fields/groups.ts`) той же транзакцией убирает её из прав всех ролей; в журнал `field_group.deleted` — id изменённых ролей.
- Скрытие: `GET /api/v1/field-groups` и `GET /api/v1/fields` не отдают скрытые группы и их поля, `GET /api/v1/fields/:id` скрытого поля — 404 как несуществующего; `custom` в ответах сделки, контакта и организации — без кодов скрытых полей (`visibleCustom`, а с ним и списки `/deals`, `/contacts/list`, `/organizations/list`, канбан и выгрузка — их колонки по полям подключает тикет 07); `GET /deals/:id/history` и лента `/{deals,contacts,organizations}/:id/timeline` не отдают строки `custom.<код>` по невидимым полям (фильтр в запросе, страницы не короче).
- Запись (`prepareCustom`): поле скрытой группы — 422 `CUSTOM_FIELD_UNKNOWN` тем же телом, что неизвестный код (сначала проверяются все коды на «неизвестный», потом остальные отказы — порядок отказов не выдаёт скрытое поле); поле группы «только чтение» — 403 `CUSTOM_FIELD_READ_ONLY` (`details.field`). Значения скрытых полей запись других кодов не трогает.
- Экран: «Налаштування → Ролі», раздел «Групи полів» — группы по сущностям, у каждой выбор «Бачить і змінює / Лише читання / Приховано»; группа без записи показывает доступ по правам, выбор пишет запись; у администратора — только «Бачить і змінює», без выбора. Группы приходят запросом `fieldGroups` клиента ролей (`apps/web/src/routes/settings/roles-api.ts`): три `GET /api/v1/field-groups`, сущность без права смотреть (403) — без групп. Переводы — `apps/web/src/locales/{uk,ru}/settings.json` (путь тикета `apps/web/src/i18n/locales` не существует).
- Миграции нет: права лежат в `role.permissions` (JSONB), форма уже предусматривала `fieldGroups`.

Решено без владельца — подтвердить:

- Запись в поле скрытой группы — 422 как неизвестный код (из текста тикета).
- Запись в поле группы «только чтение» — 403 и тогда, когда передано прежнее значение.
- Строки истории по пользовательскому полю показываются, только пока поле есть и роль его видит: история окончательно удалённого поля не показывается никому (у удалённого поля не узнать, в какой группе оно было, а показать её роли со скрытой группой — утечка).
- Описание скрытого поля по id — 404, как несуществующего.
- Выбор доступа в редакторе всегда пишет запись о группе; вернуть группу к «по правам» можно только убрав запись через API.
- Пользователь с правом «поля» (конструктор), которому группа скрыта, её тоже не видит в `GET`-описаниях (конструктор тикета 05 у такого пользователя не покажет группу).

## Что сделать

Колонка `custom jsonb not null default '{}'` с проверкой «это объект» у `deal`, `contact`, `organization` уже есть из тикета 01 (миграция `0016_fields`); миграция этого тикета (следующий свободный номер миграции) добавляет к ней GIN-индекс `jsonb_path_ops`. Ключ — код поля, значение — по типу; пустое значение — отсутствие ключа (решено без владельца, подтвердить):

| Тип | Значение |
|---|---|
| текст, адрес | строка, обрезанная по краям, до 500 символов (решено без владельца, подтвердить) |
| большой текст | строка до 10 000 символов (решено без владельца, подтвердить) |
| число | число |
| деньги | `{ "amount": число ≥ 0 с двумя знаками, "currency": "EUR" \| "UAH" \| "USD" }` |
| дата | `"YYYY-MM-DD"` |
| время | `"HH:MM"` |
| интервал дат | `{ "from": дата, "to": дата }`, `from` ≤ `to` |
| один вариант | id варианта (не архивного — для нового значения) |
| несколько вариантов | массив id вариантов без повторов |
| да/нет | `true` / `false` |
| телефон | строка E.164, приведённая той же функцией, что телефоны контактов (эпик `crm-deals`, по умолчанию Украина) |
| email | строка в нижнем регистре, проверенная по формату |
| ссылка | строка `http://` или `https://` (другие схемы, в том числе `javascript:`, — 422) |
| пользователь | id участника проекта; для нового значения — только не отключённого |

Одна функция проверки и приведения значений в `packages/shared/src/fields/` — её используют API здесь, формы интерфейса и позже приём регистраций.

Запросы: создание и изменение сделки, контакта, организации в `/api/v1` принимают `custom: { код: значение | null }`; изменяются только переданные коды, `null` очищает. Неизвестный или архивный код — 422 с кодом поля; значение не по типу — 422 с кодом поля и причиной. Ответы карточки и списка содержат `custom` по кодам. Первое значение поля ставит `first_value_at` в описании (тикет 01) одним условным UPDATE.

История: каждое изменение значения пишется общей функцией `change_log` (тикет 03 эпика `crm-deals`) — «поле `custom.<код>`, было → стало», с автором; у вариантов пишутся id, отображение подставляет текущие названия.

Безопасная смена типа поля с данными (сверх тикета 01): текст → большой текст (данные не меняются), число → текст (числа переписываются строками), один вариант → несколько вариантов (id переписывается массивом из одного id). Переписывание — фоновая задача pg-boss порциями; пока она идёт, поле только для чтения (запись — 409), после — тип меняется. Любая другая смена типа поля с данными — 409 «создайте новое поле».

Тикет не отправляет событий; значения меняются только запросом пользователя (ADR 0003).

## Результат

- Миграция `packages/db/migrations/0017_field_values.ts`: GIN-индексы `deal_custom_idx`, `contact_custom_idx`, `organization_custom_idx` (`jsonb_path_ops`); колонка `field_definition.converting_to` (идёт смена типа поля с данными); триггер `field_definition_guard` пускает смену типа поля с `first_value_at` только безопасную (текст → большой текст, число → текст, один вариант → несколько), во время смены — только на её тип (`FD002`); проверка `change_log.field` допускает `custom.<код>`. Откат — тестом `project-isolation.test.ts` (до пустой схемы и снова вверх), в цепочке отката `deals.test.ts` 0017 — первой.
- `packages/shared/src/fields/values.ts`: `normalizeFieldValue` — одна проверка и приведение по 15 типам (причины отказа `FieldValueProblem`), `typeChangeWithValues` — список безопасных смен. Телефон — `normalizePhone` контактов, email — `normalizeEmail`.
- `apps/api/src/fields/values.ts` — единственное место чтения и записи `custom` (сюда тикет 03 добавит права групп): `prepareCustom` проверяет и ничего не пишет, `customUpdate` меняет только переданные коды одним выражением SQL, `finishCustom` ставит `first_value_at` одним условным UPDATE и пишет «было → стало» (`custom.<код>`, у вариантов — id), `visibleCustom` отдаёт в ответах только коды действующих полей. Описания читаются `FOR KEY SHARE`: смена типа и архив ждут конца записи значений.
- Запросы: `POST`/`PUT /api/v1/deals`, `/contacts`, `/organizations` (и новый контакт внутри создания сделки) принимают `custom`; `custom` не объект — 400 с `path: custom`; неизвестный, архивный или удаляемый код — 422 `CUSTOM_FIELD_UNKNOWN` (`details.field`); значение не по типу — 422 `CUSTOM_FIELD_INVALID` (`details.field`, `details.reason`); идёт смена типа — 409 `CUSTOM_FIELD_CONVERTING`. Отказ не меняет и остальных полей запроса. `custom` есть в карточках, `GET /deals`, `/contacts`, `/contacts/list`, `/organizations`, `/organizations/list`.
- Смена типа (`PUT /api/v1/fields/:id`): текст → большой текст — сразу; число → текст и один вариант → несколько — 202, `convertingTo`, задача pg-boss `field-retype` (`apps/api/src/fields/retype.ts`, порции по 500, каждая в своей транзакции проекта; `updated_at` записей не трогает), в конце — тип поля и запись журнала `field.updated` «тип: было → стало». Повтор той же смены снова ставит задачу (поле не останется только для чтения навсегда, если очередь исчерпала повторы); другая смена во время задачи — 409 `FIELD_CONVERTING`; любая иная смена поля с данными — 409 `FIELD_TYPE_LOCKED`.
- Вне списка файлов тикета, но нужно для работы: `apps/api/src/index.ts` (очередь смены типа подключена к API).

Решено без владельца — подтвердить:

- Пустая строка, строка из пробелов и пустой список значений — то же, что `null`: ключ убирается.
- Большой текст по краям не обрезается (текст и адрес — обрезаются, как в таблице).
- Ссылка — до 2048 символов; только `http://` и `https://` с непустым хостом, без пробелов и без `user@` в адресе; хранится как введена (без приведения).
- Несколько вариантов: повторы убираются молча, порядок — порядок вариантов в поле (тот же набор — то же значение, лишней строки истории нет).
- Архивный вариант и отключённый пользователь, которые уже лежат в значении записи, можно записать снова (запрет — только для нового значения).
- Значения архивного поля в ответах не отдаются, но лежат в `custom` до возврата из архива или окончательного удаления.
- Создание записи с `custom` истории не пишет (как и остальные поля новой записи), но ставит `first_value_at`.
- Переписывание значений при смене типа истории записей не пишет (значение то же, меняется вид), только журнал поля.
- Смена типа с переписыванием отвечает 202, а не 200.

Найдено для тикета 07 (фильтры и скорость): оператор `@>` (`jsonb_contains`) в PostgreSQL не LEAKPROOF, поэтому под row-level security роль приложения не может искать GIN-индексом `custom` — условие проверяется фильтром после политики (проверено планом запроса на PostgreSQL 18.6). Индекс построен, изоляция проверена тестом, но для фильтра по значению роли приложения он не работает; путь — в тикете 07.

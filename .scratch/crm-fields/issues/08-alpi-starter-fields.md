## Что сделать

Две части; вторая начинается только после подтверждения владельца.

**1. Таблица на просмотр.** `docs/setup/alpi-start-fields.md` — стартовый набор пользовательских полей проекта ALPI по разбору `docs/research/pipedrive-fields-audit.md`: поля с решением «Перенести» у сделок, контактов и организаций ALPI (группа «Franch AI» и поля без группы, относящиеся к AI-школе) и четыре поля «Уточнить». Колонки: название uk и ru, код, сущность, группа, тип (из 15), варианты (число и список), обязательность («завжди» / «з етапу X воронки P» / «при виграші»), видимость по воронкам («ALPI», «Платформа (допродаж)», «Автовебінари»), «важливе», «часто фільтрують», поле Pipedrive — источник, примечание. В таблице только названия и типы — без персональных данных: варианты, которые являются именами сотрудников, не переносятся, такие поля становятся типом «пользователь».

Отдельным списком в конце таблицы — что не заводится и почему, со ссылкой на правило:

- атрибуция и вебинар (Форма, URL, UTM, идентификаторы кликов, Дата регистрации, просмотр вебинара, город, устройство, ОС) — данные регистрации, эпик приёма;
- «Сделка WFP», «Страница оплаты», дата брони и ожидаемый платёж — платёж;
- «Bitrix ID» — внешний идентификатор;
- дубли системных полей («Дата виграної угоди», «Telegram» сделки → контакт, «Язык» контакта → системный язык общения);
- поля «Франча» — заводятся при переезде «Франча», не здесь.

Вопросы владельцу — строками таблицы с пометкой «уточнить»: поля «Уточнить» из разбора (Рід діяльності, Кваліфікація, Потенциальный бюджет, Тип закриття), «Первичное касание» (поле сделки или данные регистрации), «Відділ продажів» (поле или команда), «Потік» и «Курс у KWIGA» (в разборе — отдельные сущности, которых в MVP нет; предложено: «Потік» — один вариант, «Курс у KWIGA» — не заводить). Обязательность «при виграші» — пункт «Виграно» в правиле «з етапу X» (тикет 04; решено без владельца, подтвердить).

**2. Скрипт заведения** — после того как владелец подтвердил таблицу (отметка с датой в этом тикете). Подтверждённая таблица переносится в данные стартовой настройки проекта: `pnpm project-preset alpi <id проекта>` (эпик `crm-deals`) заводит группы, поля, варианты и правила. Служебная роль; повторный запуск ничего не дублирует и не меняет поля, уже исправленные администратором (поиск по коду). `pnpm seed` создаёт эти поля в тестовом проекте ALPI и заполняет правдоподобными выдуманными значениями часть сделок (нужно приёмке, тикет 09).

Тикет не отправляет событий (ADR 0003).

### Часть 2: скрипт заведения

- Данные — `packages/db/src/presets/alpi-fields.ts` (раздел 1 таблицы): 4 группы, 20 полей — 19 у
  сделки, 1 у контакта. Из раздела 2 в раздел 1 перешли «Рід діяльності», «Тип закриття»,
  «Потік», «Первинний дотик», «Відділ продажів»; в «Не заводится» — «Кваліфікація»,
  «Потенційний бюджет», «Курс у KWIGA». Таблица обновлена: раздел 2 — список принятых решений.
- `pnpm project-preset alpi <id>` (`applyProjectPreset`) после воронок и причин заводит поля,
  которых в проекте нет по коду (архивные тоже считаются), с группами (по названию; нет — новая в
  конце), вариантами, видимостью по воронкам, отметками и правилами. Существующее поле не
  трогается: название, группа, варианты, правила — как оставил администратор. Этапа или воронки из
  правила в проекте нет — правило не заводится, команда печатает предупреждение. Запуски по одному
  проекту идут по очереди (`pg_advisory_xact_lock`): у группы полей нет кода, без очереди
  одновременный второй запуск задвоил бы группы. Журнал проекта — `project.preset_applied` с
  созданными группами и полями.
- `pnpm seed`: поля создаёт стартовая настройка; у части сделок ALPI — выдуманные значения
  (`alpiCustom` в `apps/api/src/seed/plan.ts`, свой генератор с зерном: люди и сделки при том же
  зерне не изменились). Поле, обязательное по правилу, заполнено у сделок, дошедших до этапа
  правила, и у выигранных. Каждое значение проходит `normalizeFieldValue`
  (`packages/shared/src/fields/values.ts`), полям со значениями ставится `first_value_at`, как в
  API. `--reset`: значения уходят со сделками, поля — с проектом; поле, заведённое руками, держит
  проект, как воронка не из настройки.
- Тесты (`apps/api/src/cli/project-preset.test.ts`, `apps/api/src/cli/seed.test.ts`) краснеют на
  мутантах: поиск полей не по коду, правило «при виграші» на первом этапе, этап правила со сдвигом,
  опечатка в названии этапа в данных, без очереди запусков, без `first_value_at`, без значений у
  выигранных сделок, без проверки ручного поля при `--reset`.

Решено без владельца — подтвердить:

- «Первинний дотик» и «Відділ продажів»: у строк раздела 2 не было отдельного предложения; принят
  вариант самой строки — поле сделки со списком. У «Первинний дотик» заведён единственный
  известный код «4».
- «Тип клієнта»: варианты заведены с «…», как в разборе, — полных названий из Pipedrive в
  репозитории нет; администратор поправит их в конструкторе.
- Видимость «ALPI, Платформа (допродаж), Автовебінари» заведена как «выбранные воронки», а не «все»:
  новая воронка проекта поле не показывает, пока администратор её не добавит.

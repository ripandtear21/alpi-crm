## Результат

- Миграция `packages/db/migrations/0005_audit.ts` (номер 0005, а не 0006: тикет слит раньше тикета 06). Журнал проекта `audit_log` — с RLS, роль приложения только добавляет и читает. Системный журнал `system_audit_log` (входы, выходы, 2FA, действия владельца системы) роль приложения только пополняет, читает его функция `system_audit_events` с проверкой владельца системы (граница доверия — та же, что у `create_project`: защищает от ошибок логики API, не от скомпрометированной роли приложения). Изменять и удалять записи роль приложения не может; очистка неудачных входов старше 90 дней (`purgeExpiredFailedSignIns`) — только служебной ролью.
- Пишутся: вход («пароль принят» и «вход» после кода 2FA), неудачный вход (email попытки сохраняется только если похож на email и не длиннее 254 символов, иначе пусто с причиной), выход (до удаления сессии), включение и выключение 2FA, действия владельца через плагин admin (создание пользователя, бан, снятие бана, отзыв сессий), создание, изменение и удаление ролей, смена роли участника «было → стало». Правило «нет записи — нет действия»: при сбое журнала действие отменяется (вход — с удалением созданной сессии).
- Вход под чужой учётной записью и удаление пользователя через плагин admin выключены. Общий потолок: больше 100 неудачных входов в минуту — дальше без email, с пометкой `flood`.
- Функции записи для будущих эпиков: `audit.record`, `audit.recordSystem` (`apps/api/src/audit/record.ts`), коды действий — `packages/shared/src/audit.ts`. Экран «Настройки → журнал» (право «настройки проекта»), фильтр по действию и пользователю, постраничная подгрузка.

Type: task
Status: done 2026-11-04T11:13Z
Blocked by: 02, 03

## Что сделать

API: создать проект (только владелец системы), список проектов пользователя (где он участник), выбор текущего проекта. Промежуточный слой Hono: по сессии и выбранному проекту проверяет участие пользователя и выполняет обработчик внутри `withProject` (тикет 02); нет участия — 403. Клиент: переключатель проекта в шапке, данные одного проекта за раз (ADR 0001).

apps/api/src/projects/**, apps/api/src/middleware/project-context.ts, apps/web/src/components/project-switcher/**, packages/db/migrations/**.

## Результат

- Миграция `packages/db/migrations/0003_projects.ts`: функции базы `create_project` и `user_projects` с правами владельца (SECURITY DEFINER), `search_path = pg_catalog, pg_temp`, таблицы со схемой, EXECUTE только у `alpi_app`. `create_project` повторно проверяет, что вызывающий — незаблокированный владелец системы; создатель сразу становится участником проекта (роль пока пустая — роли в тикете 05). `user_projects` отдаёт только участия самого пользователя.
- API: `POST /projects` (только владелец системы), `GET /projects` (мои проекты). Промежуточный слой `apps/api/src/middleware/project-context.ts`: проект приходит заголовком `X-Project-Id`; проверка сессии с пройденной 2FA, проверка участия, `set_config` и обработчик — в одной транзакции (`withProject`). Нет участия, нет проекта, неверный id — одинаковый 403 `PROJECT_FORBIDDEN`; нет заголовка — 400 `PROJECT_REQUIRED`. Ошибка обработчика откатывает транзакцию. Всё, что зарегистрировано после слоя, работает в контексте проекта.
- Долг тикета 03 закрыт: API не стартует, если его роль состоит (прямо или через группы) в роли с SUPERUSER или BYPASSRLS (`packages/db/src/app-role.ts`).
- Клиент: переключатель проекта в шапке (`apps/web/src/components/project-switcher/`), выбор в localStorage как подсказка (сверяется со списком с сервера), при смене проекта сбрасывается кэш данных проекта. На 375 px проект стоит своей строкой и не обрезается (проверено в браузере).
- 102 теста. Проверка: VERIFIED с первого раунда (сверка отчёта и отдельный разбор безопасности); мутации проверочного кода делают тесты красными. Gate full зелёный.

Долг:
- Без своих тестов: проверка «только владелец» в API (`projects.ts:49`; сейчас её дублирует база), условие «не заблокирован» в `create_project` (`0003_projects.ts:38`), ключ кэша списка проектов с id пользователя (`router.tsx:70`).
- Укрепление: у `alpi_app` есть `update` на `user.role` — при SQL-инъекции повторная проверка владельца в базе не спасёт (рассмотреть в тикете 05); `POST /projects` защищён от подделки запроса только SameSite=Lax — добавить проверку Origin или Content-Type; транзакция проекта держит соединение всё время обработчика — задать `idle_in_transaction_session_timeout` роли приложения (тикет 10) и читать тело до транзакции.
- Нет экрана создания проекта (только API); снятое участие клиент пока не обрабатывает.

Решения без владельца — подтвердить: проект передаётся заголовком, а не в адресе (ссылка не указывает проект); создатель проекта становится его участником.

## Что сделать

## Результат

- Миграция `packages/db/migrations/0006_teams.ts` (номер 0006: тикет 07 с `0005_audit` слит раньше). Команды проекта с RLS, участник — не больше чем в одной команде (связь по паре «проект, команда»), у команды один тимлид. Отключение участника спрашивает заглушку открытых сделок и отказывает `HAS_OPEN_DEALS`. Охват «команда» из тикета 05 считается по этим командам.
- Правила `guard.ts`: команды меняет только администратор (`TEAMS_ADMIN_ONLY`), в том числе при заведении нового участника сразу в команду. Отключены `/admin/update-user` и `/admin/set-user-password` (404): владелец системы не меняет чужие имя, почту и пароль в обход проекта.
- Журнал проекта в той же транзакции: участник добавлен, создан (без пароля), отключён, включён, смена роли и команды «было → стало»; команда создана, изменена, удалена, сменён тимлид. При сбое журнала действие отменяется (500).
- Смена временного пароля: отказ `PASSWORD_UNCHANGED`, закрытие других сессий, флаг временного пароля снимается после записи в журнал.
- Проверка: два раунда, отчёт исполнителя и безопасность — VERIFIED во втором раунде. Gate full зелёный (lint, typecheck, test, build), `pnpm verify` — 209 тестов.
- Долги (low): смена флага «принимает новые сделки» не пишется в журнал; смена пароля не попадает в системный журнал (нет `auth.password_changed`); `admin.user_created` из `/members/new` пишется в системный журнал без автора; при сбое журнала на `/members/new` учётная запись Better Auth остаётся без проекта (`shortcut:` в `service.ts`); нет теста отката команд при сбое журнала.

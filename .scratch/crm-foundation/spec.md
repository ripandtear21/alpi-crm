# Эпик: каркас, вход, проекты, роли

Первый эпик реализации CRM — «Эпик 1» раздела 12 спецификации MVP ([`.scratch/crm-mvp/spec.md`](../crm-mvp/spec.md)). Решения — в спецификации и тикетах карты `crm-mvp`; термины — `GLOSSARY.md`; изоляция проектов — `docs/adr/0001-izolyatsiya-proektov.md`.

Готово, когда: администратор входит с двухфакторной аутентификацией, создаёт проект, роли и пользователей; тест доказывает, что запрос в контексте проекта A не видит строк проекта B даже без фильтра в коде; проверки (`pnpm verify`) и CI зелёные.

## Решения эпика (приняты без владельца по его поручению 2026-11-04 — подтвердить)

- Стек — по рекомендации исследования (spec.md, раздел 10): pnpm-монорепозиторий, Node 22+, TypeScript strict, Hono (API), React + Vite + TanStack Router/Query (клиент), PostgreSQL, Kysely + kysely-codegen, Better Auth, pg-boss, i18next.
- Линтер и форматирование — Biome; тесты — Vitest; e2e — Playwright (позже).
- На машине разработки нет Docker и PostgreSQL: тесты с базой поднимают настоящий PostgreSQL через npm-пакет `embedded-postgres` (без Docker). `docker-compose.yml` нужен для сервера.
- Staging и выкладка требуют проекта Railway владельца (ADR 0002, хостинг сменён с Hetzner) — тикет 10, ждёт владельца.
